# 세부 구역 추천

> Route Viewer 문서 · [← README 목차로](../README.md#문서-목차)

## 세부 구역 추천 — "강남"이 아니라 "테헤란로 업무지구 · 테헤란로 구간"

### 공간을 세 단계로 나눈다

| 단계 | 무엇 | 예 | 어디서 관리 |
|---|---|---|---|
| 1단계 **상위 운영 구역** | 지금까지 쓰던 큰 구역 | 강남 · 판교 · 시흥 | [설정] 탭 |
| 2단계 **세부 수집 구역** | 비슷한 교통 특성을 갖는 생활권·장소 유형 | 테헤란로 업무지구 · 학교 인접 도로 · 아파트 진출입부 | [추천 주행] 탭 → 세부 구역 관리 |
| 3단계 **실제 추천 구간** | 운전자가 실제로 달릴 도로 구간 | 테헤란로(이 구역 안 6.7km 구간) | 자동 — HD Map 도로에서 뽑습니다 |

추천 카드에는 세 단계가 모두 나옵니다: `강남 → 테헤란로 업무지구(업무지구) → 테헤란로 · 평일 퇴근 피크 · 일몰 전후 · 17:30~19:30 · 서쪽 방향 2회`.

### 장소 이름을 지어내지 않는다 (가장 중요한 규칙)

장소·도로·학교·IC 이름은 **사용자가 직접 적었거나 지도 데이터에 실제로 적혀 있는 것만** 씁니다.

- 도로 이름·구간·길이·시작/끝 좌표 → **HD Map**(`src/data/hdmap_gangnam_roads.json`, `hdmap_seocho_roads.json`).
  이름이 `-` 인 도로는 **"이름 없는 도로"** 로 두고 이름을 만들지 않습니다.
- 도로 등급은 이름에 그렇게 적혀 있을 때만 단정합니다(`경부고속도로` → 고속도로). `올림픽대로`처럼 이름만으로
  알 수 없으면 **확인 불가**입니다(OSM 태그 `highway=motorway` 가 확인되면 그때 등급을 씁니다).
- 학교를 찾았다고 주변을 어린이보호구역이라고 단정하지 않습니다 — 장소 유형 이름부터 **"학교 인접 도로"** 이고,
  카드에 `어린이보호구역 지정 여부는 지도 데이터로 확인되지 않았어요 — 보호구역 여부 확인 필요`라고 적습니다.
- IC·JC 램프는 HD Map 에 이름이 없어서 **이름을 만들지 않습니다**. 필요하면 사용자가 직접 구역으로 등록하세요.

### 장소 유형과 후보 시간대

유형마다 "볼 만한" 시간대와 예상 상황이 정해져 있습니다. **후보일 뿐이고, 실제 추천 여부는 그 구역의
데이터 부족도가 정합니다** — 시간 규칙만으로는 추천하지 않습니다.

| 유형 | 후보 교통 시간대 | 예상 가능한 상황(일부) |
|---|---|---|
| 업무지구 | 출근 피크 · 점심 피크 · 퇴근 피크 | 정체 · 빈번한 차선 변경 · 버스 정차 · 택시 승하차 · 교차로 꼬리물기 |
| 상업지구 | 점심 피크 · 퇴근 피크 · 야간 | 보행자 · 택시 승하차 · 배달 오토바이 · 불법 주정차 |
| 학교 인접 도로 | 출근 피크 · 오후 비피크 (등교 07:30~09:00 · 하교 12:30~16:30 **후보**) | 어린이 보행자 · 통학버스 · 갑작스러운 횡단 · 시야 가림 |
| 아파트·주거단지 진출입부 | 출근 피크 · 퇴근 피크 · 오후 비피크 | 단지 진출입 차량 · 이중주차 · 시야 가림 · 자전거·PM |
| 종합병원 주변 | 출근 피크 · 오전/오후 비피크 | 구급차 · 승하차 정차 · 주차 대기행렬 |
| 전통시장 주변 | 오전/오후 비피크 | 노상 적치물 · 배달 차량 · 좁은 도로 교행 |
| 환승역·버스정류장 밀집 | 출근 피크 · 퇴근 피크 | 버스 정차 · 보행자 급증 · 정류장 대기 차량 |
| 도시고속도로 **본선** | 출근 피크 · 퇴근 피크 · 야간 | 고속 합류 · 정체 시작/해소 · Cut-in 가능성 · 터널 조도 변화 · 야간 Headlight Glare |
| 진입·진출 **램프(IC·JC)** | 출퇴근 피크 · 오후 비피크 · 야간 | 짧은 합류 구간 · 연속 차선 변경 · 진출 대기행렬 · 본선과의 속도 차이 |
| 교차로 밀집 구간 | 출근·점심·퇴근 피크 | 교차로 정체 · 좌우회전 대기 · 꼬리물기 |
| 공사 구간 | 오전/오후 비피크 | 차로 축소 · 임시 차선 · 유도원 수신호 |
| 직접 등록한 구역 | (관심 시간대를 직접 고름) | — |

**본선과 램프는 서로 다른 유형**입니다(예상 상황이 다르므로 한 구간으로 묶지 않습니다).
등록할 때 관심 시간대를 직접 고르면 그 시간대가 유형 기본값보다 우선합니다.

어린이보호구역 안전 원칙: **정문 앞 정차·반복 배회처럼 보행 안전을 방해하는 주행은 권장하지 않습니다.
제한속도와 교통법규를 지킨 정상 통과 주행으로만 수집하세요.** 카드에도 같은 문구가 나옵니다.

### 세부 구역 등록 방법 (지금은 수동 등록만)

[추천 주행] 탭 → **세부 구역 관리** → `+ 새 세부 구역`

1. 이름(예: `테헤란로 업무지구`) · 상위 구역 · 장소 유형을 고릅니다.
2. **지도에서 경계 그리기** 를 누르고 지도를 클릭해 경계를 3점 이상 찍습니다(한 점 취소 가능).
3. 관심 시간대를 고르고(선택) 메모를 적은 뒤 저장합니다.
4. 목록에서 지도 이동 · 수정 · 끄기/켜기 · 삭제를 할 수 있습니다. 끈 구역은 추천에서 빠지지만
   **GPS 기록은 그대로** 있습니다.

자동 탐지(OSM·HD Map 으로 업무지구·학교 인접 도로를 스스로 찾는 것)는 **아직 없습니다** — 아래 "단계별 구현 범위" 참고.
등록 구역의 출처는 목록에 `직접 등록` / `HD Map` / `OpenStreetMap` 으로 표시됩니다.

### 도로 구간과 주행 방향 집계

- 세부 구역 경계 안에 들어오는 HD Map 도로를 **이름별로 묶어** 그 구역 안 구간으로 만듭니다(길이·시작·끝·방위).
- GPS 기록은 **25m 안의 도로에만** 맞춥니다(Map Matching). 더 멀면 맞추지 않습니다 —
  옆 평행도로에 잘못 붙이는 것보다 "못 맞췄다"가 낫기 때문입니다. 카드에 맞춘/못 맞춘 건수를 적습니다.
- 진행 방위(직전 기록 → 지금 기록)가 도로 방향과 **60도 이내면 정방향, 120도 이상이면 역방향**으로 셉니다.
  그 사이(교차로 통과 등)는 어느 방향도 아닙니다.
- 방향 표본이 적으면(20건 미만 또는 그 도로에 맞춘 기록의 10% 미만) **방향을 단정하지 않고 "양방향"** 으로
  표시하고 그 이유를 적습니다. 정체 구간은 직전 기록과 3m 도 안 움직여 방위를 못 구하는 점이 많습니다.
- 방향별 수집량이 다르면 **적게 모인 쪽**을 권합니다(`이 구간 전체에서 동쪽 24건 · 서쪽 3건 — 적은 쪽을 권합니다`).

### 추천 경로의 의미

라우팅 엔진이 없으므로 **Turn-by-Turn 경로를 만들지 않습니다.** 추천 구간은
**HD Map 에 실제로 있고, 그 구역에서 우리 차가 실제로 달려서 매칭된 도로**만 씁니다.
카드에는 도로 이름 · 구간 길이 · 시작/끝 좌표 · 권장 방향 · 권장 반복 횟수(편도 기준)를 적습니다.

### 추천 지도

추천 탭의 지도에 세부 구역 경계(점선)와 추천 구간을 우선순위 색으로 그립니다.

```text
매우 높음 빨강 · 높음 주황 · 보통 노랑 · 낮음 회색 · 시작점 ● · 끝점 ◎
```

카드의 **지도에서 보기** 를 누르면 그 구간으로 지도를 옮기고 강조합니다(카드와 지도는 같은 좌표를 씁니다).

### 장소 신뢰도 (추천 점수와 다릅니다)

| 수준 | 조건 |
|---|---|
| 높음 | HD Map + OSM + 실제 GPS 주행 이력이 모두 있음 |
| 보통 | 지도 데이터와 GPS 중 일부만 있음 |
| 낮음 | 사용자 수동 등록이거나 지도 근거가 제한적 |

**추천 점수가 높아도 장소 근거가 약하면 신뢰도는 낮게 표시합니다.** 카드에 근거 목록
(`HD Map 도로 구간 / 이 구역 GPS 기록 375건 / 사용자 직접 등록 구역`)을 함께 적습니다.

### 지도 데이터가 없을 때

- HD Map 은 **강남·서초**만 있습니다(`SubZones.HDMAP_PARENT_SOURCES`). 판교·시흥 등에 세부 구역을 만들면
  구간 없이 **구역 단위로만** 추천하고 `HD Map 도로 데이터가 없어 구간을 표시하지 못했어요`라고 적습니다.
- OSM(Overpass)은 네트워크가 막히면 쓸 수 없습니다 — 그때는 자동 탐지·POI 확인을 하지 않고 그 사실을 밝힙니다.

### 단계별 구현 범위

| 단계 | 내용 | 상태 |
|---|---|---|
| 1단계 | 수동 세부 구역 등록 · 구역별 GPS 집계 · 구체적 시간/부족량 추천 · 지도 표시 | **완료** |
| 2단계 | HD Map 도로 구간 자동 추출 · 본선/램프 유형 분리 · 도로 등급 판정 | **부분 완료**(HD Map 기반 구간·유형 분리 완료, OSM POI 자동 탐지 미구현) |
| 3단계 | Map Matching · 방향별 수집량 · 연결된 추천 경로 · 실제 Edge Case 이벤트 연계 | **부분 완료**(25m 매칭·방향별 집계 완료, 연결 경로 생성과 이벤트 연계 미구현) |
