# 자동 분석 추천

> Route Viewer 문서 · [← README 목차로](../README.md#문서-목차)

## 자동 분석 추천 — 상위 구역만 고르면 도로 구간까지 스스로 찾는다

[추천 주행] 탭 맨 위 **자동 분석 추천**에서 분석할 상위 구역(강남 등)만 고르면 됩니다.
세부 구역을 직접 그리지 않아도, 지도(HD Map)와 우리 GPS 기록으로 도로 구간과 세부 구역을 자동으로 만듭니다.

### 1) 도로 Graph 와 Segment 자동 생성

HD Map 은 짧은 선 조각(중앙값 57m, 강남 3,350개)으로 들어옵니다. 조각의 끝점을 노드로 묶어 도로망 Graph 를
만들고(강남 노드 2,545개 · 교차로 1,131개), 조각을 이어 붙이되 다음 지점에서 끊습니다.

```text
교차로(끝점을 세 갈래 이상이 공유하는 노드)
도로명이 바뀌는 지점
도로 등급이 바뀌는 지점(지도에 등급이 있을 때만)
상위 구역 경계 밖
최대 길이 800m
```

너무 짧은 꼬리(30m 미만)는 같은 도로의 이웃 구간에 붙입니다. 강남 전체 기준 **1,149개 구간**이 나오고,
계산은 30ms 안쪽입니다. 각 구간은 `id · geometry · roadName · roadClass · 시작/끝 노드 · 교차로 여부 ·
길이 · 진행 방위 · semanticTypes · source(HD Map 조각 id 들)` 를 가집니다.

**id 는 다시 분석해도 같습니다** — `상위 구역 + 도로명 + 양끝 좌표 지문(fnv1a) + 길이`로 만들기 때문입니다.
그래서 사용자가 고친 내용(보정)이 재분석 후에도 그 구간에 그대로 붙어 있습니다.

### 2) 자동 세부 구역 분류 — "있는 근거로만"

구간마다 성격을 판정하고 **왜 그렇게 봤는지 문장으로 남깁니다**. 근거 우선순위는
`공식 데이터 > 지도(HD Map·OSM 등급) > 지도 POI > 우리 주행 기록(관측) > 도로망 모양` 입니다.

| 유형 | 필요한 근거 | 판정 기준 |
|---|---|---|
| 고속화도로 본선 / 진입·진출 램프 | 지도 | 도로명에 `고속도로`가 있거나 OSM `highway=motorway/trunk`(본선) · `*_link`(램프) |
| 공식 어린이보호구역 | 공식 데이터 | 공식 보호구역 데이터가 그 구간 120m 안에 있을 때만 |
| 학교 인접 도로 | 지도 POI | 학교 POI 만 있을 때 — **보호구역이라고 말하지 않습니다** |
| 업무/상업/병원/시장/역·환승/주거단지 진출입 | 지도 POI | 해당 POI 밀도(업무 3곳↑, 상업 5곳↑, 역 2곳↑ 등) |
| 고속 주행 구간(관측) | 주행 기록 | 그 구간 평균 속도 55km/h 이상(기록 40건 이상) |
| 합류·분기 후보(관측) | 주행 기록 | 고속 구간과 이어지는 400m 이하 구간인데 평균 속도가 20km/h 이상 낮을 때 — **후보**로만 |
| 저속·정체 잦은 구간(관측) | 주행 기록 | 10km/h 미만 주행 비율 35% 이상 |
| 출퇴근 집중 구간(관측) | 주행 기록 | 수집 시간의 55% 이상이 출근·퇴근 피크 |
| 교차로 밀집 구간 | 도로망 | 양끝이 교차로이면서 150m 이하 |
| 유형 확인 불가 | — | 위 근거가 하나도 없을 때(추측하지 않습니다) |

**지도 POI 는 어디서 오나** (`src/js/poi-data.js`) — 실제 지도 데이터만 씁니다.

- **[지도 POI 받기(OSM)]** 버튼을 눌렀을 때만 OpenStreetMap(Overpass)에서 받습니다(자동으로 받지 않음).
  학교·업무시설·상업시설·병원·시장·역/정류장·아파트 단지. 누적 지도와 같은 조회기(미러·쿨다운)를 쓰고 브라우저에 캐시합니다.
- 누적 지도가 Coverage 계산 때 이미 받아 둔 **아파트 단지 경계**(`landuse=residential + residential=apartments`)도 씁니다.
  단지는 중심점이 아니라 **경계선**과 도로 사이 거리로 인접을 판정합니다.
- **받지 않은 종류는 "0곳"이 아니라 "확인 안 됨"**이라 그 유형 분류는 하지 않습니다. 공식 어린이보호구역은 OSM 에서 만들지 않습니다.
- 아무 POI 도 없으면 화면에 **"지도 POI 데이터 없음"**이 뜨고 도로망·주행 기록만으로 분류합니다.

**"미방문·부족"은 성격이 아니라 상태**라서 유형으로 쓰지 않고 점수 근거로만 씁니다
(그렇게 하지 않으면 아직 안 가본 도로가 전부 한 덩어리로 묶입니다).

성격이 같고 **도로명도 같은** 이웃 구간을 묶어 자동 세부 구역을 만듭니다(한 구역 최대 3km · 12구간).

### 3) 이름 — 지어내지 않는다

- 도로명은 HD Map 에 적힌 것만 씁니다. 없으면 `이름 없는 구간 #4 (약 37.5012, 127.0431)`.
- 자동 구역 이름은 `대표 도로명 + 자동 판정 유형 + 번호`(예: `테헤란로 저속·정체 잦은 구간(관측) #1`).
- 존재를 확인하지 못한 **학교명·IC/JC명·상권명은 만들지 않습니다.** 모든 이름에 `nameBasis`(근거)가 붙습니다.

### 4) GPS Map Matching 과 집계

- 기록을 **25m 안의 도로 구간에만** 붙입니다(옆 평행도로 오매칭 방지). 더 멀면 "못 맞춤"으로 셉니다.
- 진행 방위(직전 기록 → 지금 기록, 3m 이상 이동한 경우)가 구간 방향과 60° 이내면 정방향, 120° 이상이면 역방향.
- 집계 단위: **구간 × 방향 × 평일/주말 × 교통 시간대 × 조도 × 날씨**. 같은 도로도 방향이 다르면 다른 칸입니다.
- 구간별로 수집 시간(90초 규칙)·방문(날짜×차량)·마지막 방문·평균 속도·저속 비율·차량별 기록 수와
  **구간 Coverage**(구간을 20m 칸으로 나눠 실제로 지나간 칸 비율)를 계산합니다.
- 한 기록은 한 구간에만 붙습니다(중복 집계 없음 — 테스트로 확인).

### 5) 추천 점수 (가중치는 설정에서 조정)

| 항목 | 기본 가중치 | 무엇을 보나 |
|---|---|---|
| 시간대 부족도 | 20% | 그 칸의 수집 시간 / 목표(기본 60분) |
| 구간 Coverage 부족도 | 20% | 구간 20m 칸 중 지나간 비율 |
| 방향별 부족도 | 15% | 정/역 방향 기록 수 차이(신뢰할 때만) |
| 조도 조건 부족도 | 10% | 그 조도에서의 수집 시간 |
| 날씨 다양성 부족도 | 10% | 그 조건에서 본 날씨 종류 |
| Edge Case 가능성 | 10% | 발생 가능성(분류 근거: 공식 1.0 · 지도 0.9 · POI 0.8 · 도로망 0.7 · 관측 0.6 × 판정 신뢰도) × 이 조건 수집 부족 — 예상 상황 **개수로 올리지 않습니다** |
| 최근 미방문 기간 | 10% | 마지막 수집 이후 지난 날 |
| 차량 편중도 | 5% | 한 차량이 차지하는 비중 |

데이터가 없는 항목은 **0점으로 깎지 않고 빼고**, 남은 가중치로 다시 나눕니다(카드에 "적용 가중치 N%"로 표시).
그리고 **관련도**를 곱합니다 — 한 번도 안 가봤고 성격도 모르는 골목이 항상 1등이 되지 않도록,
우리가 실제로 다니는 구간(×1.0) > 지도로 성격이 확인된 구간(×0.8) > 그 외(×0.35). 낮춘 이유도 카드에 적습니다.
여기까지가 **Data Need Score**(데이터 부족도)입니다.

**최종 점수 = Data Need Score × 80% + Project Priority(사업 우선도) × 20%** — 비중은 자동 분석 추천 아래 "추천 점수 가중치 · 사업 우선도" 에서 0~50% 로
바꿀 수 있습니다(부족도가 중심이어야 해서 50% 까지만). 사업 우선도는 오늘 적용되는
[HD Map 우선 수집 정책](./priority-policy.md#hd-map-우선-수집-정책priority-policy)에서 그 구간이 속한 ①~⑫ 구역의 값(0~100)입니다.

- **그 조건의 목표를 이미 채운 구간에는 사업 우선도를 더하지 않습니다** — 최우선 구역이라도 충분히 모았으면 올라가지 않아
  "우선지역이라서 1등"이 되지 않습니다(테스트: 최우선·충분 18.2점 < 일반·부족 62.4점).
- 적용 정책이 없거나(기간 밖 포함) 분석 범위에 ①~⑫ 가 없으면 사업 우선도 0 → 최종 점수 = Data Need Score 그대로.
- 근거 보기에 `Data Need Score 86.4 · 사업 우선도 100 · Final Score 89.1 · 적용 정책: …` 과 계산식이 나옵니다.

**평일/주말 후보** — 그 구간의 후보 시간대 중 하나라도 한 칸 목표(60분)에 못 미친 요일 유형만 후보로 만듭니다
(평일만 부족 → 평일, 주말만 부족 → 주말, 둘 다 부족하거나 기록이 없으면 둘 다). 고른 근거가 카드에 남습니다.

### 6) 추천 카드에 나오는 것

```text
추천 1 · 매우 높음 · 점수 93.3
강남 → 테헤란로 저속·정체 잦은 구간(관측) #1 [자동] [평일] [사업 우선 구축지역 ⑤]
추천 구간: 테헤란로 · 테헤란로27길 → 논현로 (0.9km · 교차로 → 교차로)
권장 방향: 동쪽 방향        (서쪽 40건 · 동쪽 24건 — 적게 모인 쪽)
권장 조건: 평일 · 퇴근 피크 · 일몰 전후
권장 시간: 18:10~19:05     (실제 일몰에 따라 ±30분)
권장 수집: 동쪽 방향 2회(편도 약 3분)
현재 수집: 0분 / 목표 60분 · 구간 Coverage 15.9% · 이 조건 기록 없음
추천 이유: … 점수를 가장 많이 올린 항목은 시간대 부족도(100점 — 0분 / 목표 60분)입니다.
기대 상황: 정체 · 정차·재출발 · 보행자 · 끼어들기   (가능성이며 발생을 보장하지 않습니다)
신뢰도: 보통 · 근거: HD Map 도로 구간 / 이 구간 GPS 기록 51건
```

**근거 보기**를 누르면 최종 점수 구성(Data Need · 사업 우선도 · 적용 정책), 부족도 검산표(항목·현재 상태·점수·가중치·반영 점수),
자동 분류 근거, 이름 근거, 구간 표시 근거와 구간 ID, 평일/주말 후보 근거, 장소 근거 수준이 나옵니다.
추천 점수와 신뢰도는 서로 다른 값입니다.

### 7) 지도

자동 세부 구역 경계(점선) · 도로 구간(우선순위 색: 매우 높음 빨강 · 높음 주황 · 보통 노랑 · 낮음 회색 ·
추천 대상 아님 짙은 회색) · 선택한 추천 구간(청록 굵은 선, 시작 ● 끝 ◎)을 그립니다.
카드의 **지도** 버튼이나 지도의 구간을 누르면 서로 연결됩니다.

### 8) 캐시와 갱신 조건

분석은 저장소에 저장되고, 아래 지문이 바뀔 때만 그 단계부터 다시 계산합니다.

```js
graphStage = 상위 구역 경계 + 지도 데이터 + 도로망 파라미터 + 알고리즘 버전
statsStage = graphStage + GPS 데이터 지문 + 이슈 필터
```

| 바뀐 것 | 다시 하는 일 |
|---|---|
| 상위 구역 경계 · HD Map 파일 · 알고리즘 버전 | 도로망 + GPS 집계 |
| GPS Import/삭제/복원 · 이슈 상태 · 이슈 필터 | GPS 집계만(도로망 재사용) |
| 사용자 보정 | 다시 계산하지 않음(읽을 때 덮어씀) |
| 지도 POI 받기 · POI 변경 | 도로망·GPS 집계 재사용 — 유형 분류만 다시(`poiDataRevision` = 실제 POI 지문, 없으면 `none`) |
| 사업 우선 정책 변경 | 도로망·GPS 집계·POI 분석 재사용 — 추천 점수와 통계 묶음만 다시 |
| 탭 이동 | 아무것도 다시 하지 않음 |

실측(강남, 10만 건): 첫 분석 7.4초 → 이후 **0.18초**. 테스트 데이터(4천 건)에서는 103ms → 16ms.
**자동 분석 새로고침** 버튼은 캐시를 무시하고 다시 계산합니다.

### 9) 오프라인 동작

지도 POI(OSM)는 네트워크가 막히면 못 받습니다. 그때도 **HD Map 도로망과 우리 GPS 기록만으로 분석**하고,
화면 위쪽에 무엇이 있었고 무엇이 없었는지 표시합니다(`도로망 ✓ · 주행 기록 ✓ · 지도 POI — · 공식 어린이보호구역 —`).
POI 가 없으면 업무지구·학교 인접 도로 같은 시설 기반 분류를 **하지 않고**, 그 사실을 문장으로 적습니다.
마지막으로 저장된 분석 결과는 인터넷 없이도 그대로 보입니다.

### 10) 사용자 보정 (선택 사항)

자동 분류가 틀렸을 때만 고치면 됩니다. 카드 → 근거 보기 → **자동 분류 수정 / 추천에서 제외 / 보정 되돌리기**.

- 이름 수정 · 유형 변경 · 공식 데이터 확인 표시 · 추천 제외 · 다른 구역에 병합
- 보정은 **자동 결과와 별도로 저장**되고(원본 분석은 그대로), 다시 분석해도 유지됩니다(구간 id 가 안정적이라서).
- 직접 그려 만드는 세부 구역(아래 "세부 구역 추천")도 그대로 쓸 수 있지만 **필수가 아닙니다**.

### 11) 안전·법규

진입 금지·보행자 전용·사유지 도로 정보는 지도 데이터에 없으면 알 수 없습니다 — 추천에 그 한계를 적고,
**현장 표지와 교통법규를 우선**하라고 안내합니다. 어린이보호구역·학교 인접 구간에는
`안전과 법규 준수가 먼저입니다. 제한속도를 지키고, 정문 앞 정차나 반복 배회 없이 정상 통과 주행으로만 수집하세요.`
문구를 붙입니다. 위험한 저속 주행·불법 정차를 전제로 한 추천은 하지 않습니다.

### 12) 아직 못 하는 것

- **OSM POI 조회**: [지도 POI 받기(OSM)] 버튼 · Overpass 응답 파싱 · 분류(업무·학교·병원·시장·역·주거)는 구현돼 있고
  가짜 Overpass 응답과 실제 HD Map 구간으로 테스트했지만, 이 환경에서 Overpass 가 막혀 있어 **실제 OSM 응답으로 검증하지는 못했습니다.**
- 공식 어린이보호구역 공공데이터 연동(데이터 소스 미연결), IC·JC 이름(HD Map 에 없음),
  터널·교량 구분(데이터 없음), Turn-by-Turn 경로 생성(라우팅 엔진 없음), 실제 Edge Case 이벤트 연계.
- HD Map 은 **강남·서초**만 있습니다. 다른 구역은 도로 구간을 만들 수 없어 자동 분석이 비어 있습니다.
