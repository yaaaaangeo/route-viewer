# HD Map 우선 수집 정책 (Priority Policy)

> Route Viewer 문서 · [← README 목차로](../README.md#문서-목차)

## HD Map 우선 수집 정책(Priority Policy)

사업 요청에 따라 "어느 구역을 얼마나 우선 수집할지"가 수시로 바뀝니다(이번 달은 ⑤, 다음 달은 ⑩ …).
그래서 ①~⑫ 구역별 우선도를 **코드에 두지 않고 날짜별 정책(설정 데이터)**으로 관리합니다.
정책만 바꾸면 추천 점수 · 오늘 추천 Top 3 · 설정 탭 ①~⑫ 배지 · 통계 우선지역 비교가 **모두 같은 정책으로 바로** 바뀝니다.

### 정책 모양

```json
{
  "policyId": "pp-…",
  "policyName": "2026-10 우선 수집 요청",
  "effectiveFrom": "2026-10-01",
  "effectiveTo": "2026-10-31",
  "areaPriorities": { "10": 100, "9": 80, "6": 50, "5": 10 },
  "createdAt": "…", "updatedAt": "…",
  "history": [ { "이전 버전": "…" } ]
}
```

- 저장 위치: 앱 설정 `settings.priorityPolicies`(SQLite·IndexedDB 같은 규칙) — 백업·서버 동기화에 함께 들어갑니다.
- **활성 정책** = 오늘(한국 날짜)이 기간 안에 드는 정책. 겹치면 시작일이 늦은(더 구체적인) 정책 → 최근 수정한 정책 순.
  적용되는 정책이 없으면 **모든 구역 비우선**(사업 우선도 0) — 추천은 데이터 부족도만으로 정합니다.
- 모든 화면이 `src/js/priority-policy.js` 하나로 고르고 분류합니다(`resolveActive` · `classifyArea`).

### 단계(배지) — 값에서 나온다

| 우선도 | 단계 | 통계 묶음 |
|---|---|---|
| 100 | 최우선 | **정책 우선지역 (우선도 40 이상)** |
| 70~99 | 우선 | 정책 우선지역 |
| 40~69 | 보조 | 정책 우선지역 |
| 1~39 | 일반 | **일반/비우선 지역 (우선도 40 미만)** — 비교군 |
| 0 | 비우선(사업 우선도 없음) | 일반/비우선 지역 |

설정 화면 프리셋: 최우선 100 · 우선 70 · 보조 40 · 일반 10 · 비우선 0 — 숫자를 0~100 으로 직접 넣을 수도 있습니다.
추천 카드 라벨도 같은 단계에서 나옵니다(`사업 우선 구축지역 ⑩` · `우선 수집 구역 ⑨` · `보조 수집 구역 ⑥` · `일반 구역 ⑤` · `비우선 구역 ⑦`).

### 설정에서 관리하기

[설정] → **HD Map 우선 수집 정책**: 오늘 적용 정책 · 정책 목록(적용 중/예정/종료/대기) · 기간 겹침 알림 ·
`+ 새 정책`(오늘 정책을 복사해 시작) · `수정` · `복제해 새 정책` · `어제까지로 종료` · 변경 이력.

- **정책은 지우지 않습니다.** 저장 목록에서 빠져도 저장소가 보존하고, 끝난 정책은 종료일로 닫습니다.
  수정하면 이전 버전이 `history` 에 남아 "그때 어떤 정책이었는지"를 추적할 수 있습니다.
- 잘못된 정책(이름 없음 · 기간 역전 · 0~100 밖)은 저장하지 않고 이유를 보여줍니다. 백업 복원·동기화에서 잘못된 정책은 빼고 나머지를 둡니다.
- 추천을 **완료·기간 제외**할 때 그 추천을 만든 정책(이름 · 사업 우선도 · Data Need · 점수)을 함께 저장합니다
  — 숨김·완료 목록에 "당시 적용 정책: …"으로 보입니다.

### 초기 정책

정책을 한 번도 저장하지 않았다면 기존 `src/data/hdmap-priority-areas.json` 의 `priority` 값으로 만든 **초기 정책**을 씁니다
(화면에 "초기 정책 · 출처: 기존 HD Map 우선구역 설정").
`primary → 100(최우선 ⑤)` · `priority → 70(우선 ①②⑥⑨⑩)` · `normal → 0(비우선 ③④⑦⑧⑪⑫)`.
③④⑦⑧⑪⑫ 를 0 으로 두는 것은 예전 추천 점수에서 이 구역들의 사업 우선도가 0 이었기 때문입니다 —
배지를 "일반"으로 보이게 하려고 점수 의미를 바꾸지 않습니다. 수정해 저장하면 그때부터 설정 데이터로 관리됩니다.

### 정책을 바꾸면 무엇이 다시 계산되나

| 다시 함 | 다시 하지 않음 |
|---|---|
| 추천 점수(구역 · 도로 구간) · 오늘 추천 Top 3 · 설정 탭 ①~⑫ 배지 · 통계 정책 우선지역 묶음·카드·표 | GPS 집계(①~⑫ · 도로 구간) · 도로망(Road Graph) · POI 분석 |

설정 탭은 저장 즉시, 통계 현황판은 캐시된 GPS 집계로 묶음만 다시 만들어 그립니다. 날짜가 바뀌어 활성 정책이
달라질 때도 같은 방식으로 반영됩니다.

### 통계 [HD Map 우선 수집] 현황판

- 헤더와 상태 줄에 **적용 정책**과 단계별 구역(`최우선 ⑩ · 우선 ⑨ · 보조 ⑥ · 일반 ⑤ · 비우선 …`)이 항상 보입니다.
- 카드: `⑩ 최우선 지역`(정책에서 100 인 구역 — 없으면 "없음") · `정책 우선지역 비중 (우선도 40 이상)` ·
  `정책 우선지역 평균 vs 일반/비우선 지역 평균` · `가장 부족한 정책 우선지역`. 비교표 마지막 칸은 `일반/비우선 지역 평균 대비`.
- **구역 번호 안내 이미지**(`src/assets/hdmap-priority-reference.png`)는 ①~⑫ 가 지도에서 **어디인지**만 확인하는
  위치 안내용입니다. 원본의 빨간 선·번호가 "최우선" 배지 색으로 읽히지 않도록 **흑백으로 표시**하고(원본 파일은 그대로),
  "위치 안내 전용 · 우선순위와 무관" 캡션을 붙였습니다. 우선순위 색·배지는 언제나 활성 정책에서 동적으로 그립니다.
