# Import 이슈 기록 · 이슈 데이터 분리

> Route Viewer 문서 · [← README 목차로](../README.md#문서-목차)

## Import 이슈 기록 · 이슈 데이터 분리

### 왜 필요한가

주행기록 파일 중에는 "이건 좀 이상한데" 싶은 것이 섞입니다(GPS 가 튀거나, 테스트 주행이 섞였거나, 차량이 잘못
기록됐거나). 그렇다고 지워버리면 되돌릴 수 없고, 그냥 두면 그 데이터가 수집 현황·Coverage·추천 계산에 조용히
섞여 들어갑니다. 그래서 **지우지 않고 표시만 해 두고, 볼 때 골라서 거르는** 방식으로 다룹니다.

### 저장하기 전에 한 번 묻는다

파일을 끌어놓거나 골라서 불러오면, 저장 전에 확인 창이 한 번 뜹니다. 파일마다

- 파일명 · 예상 날짜 · 차량 · 레코드 수(이미 넣었던 파일이면 그렇다고 알려줍니다)
- **이 파일에 이슈가 있어요 (확인 필요)** 체크박스
- 이슈 내용 한 줄 메모(최대 200자)

를 보여주고, **취소**하면 아무것도 저장하지 않습니다. 이슈를 체크했는데 메모가 비어 있으면(공백만 있어도)
그 자리에서 막고, **파일 하나라도 어긋나면 전부 저장하지 않습니다**. 여러 파일을 한 번에 넣어도 이슈는
파일마다 따로 붙습니다 — 한 파일의 이슈가 다른 파일로 번지지 않습니다.

### 이슈는 메모가 아니라 데이터에 이어진다

중복 제거 때문에 같은 GPS 기록이 여러 파일에서 올 수 있습니다(A.xlsx 이슈 있음 / B.xlsx 정상). 그래서 이슈를
Import 이력에만 적어두면 "이 기록이 이슈 파일에서 왔는지"를 알 수 없습니다. 기록과 파일의 관계를 따로
저장합니다.

- SQLite: `record_sources(record_hash, import_id)` — 새로 들어간 기록과 **중복이라 걸러진 기록 모두** 기록합니다.
- IndexedDB: `recordSources` 저장소(같은 뜻, id = `레코드 키 + importId`).
- 날짜 요약의 조건 칸(`conditionCells`)에는 그 칸의 **이슈 마스크**가 함께 저장됩니다
  (`1` 이슈 없는 파일 · `2` 확인 필요 · `4` 확인 완료 · `0` 출처 기록이 없는 예전 데이터, OR 로 겹칩니다).
  덕분에 달력·통계·추천은 원본 기록을 다시 읽지 않고도 상태별로 나눠 셀 수 있습니다.

### 데이터 상태 필터 — 세 가지 의미

판정 규칙은 `src/js/issue-filter.js` 한 곳에 있습니다(SQLite 는 같은 뜻의 `EXISTS` SQL, IndexedDB 는 마스크로
판정하고, 두 결과가 같은지 테스트로 확인합니다).

| 값 | 화면 이름 | 의미 |
|---|---|---|
| `all` | 전체 | 이슈 여부와 상관없이 모두 |
| `clean` | 이슈 없음 | **확인 필요 이슈 파일에서만** 온 기록을 뺍니다. 정상 파일이나 확인 완료 파일에서도 왔다면 남깁니다 |
| `issue_all` | 이슈만 | 이슈로 표시한 파일에서 온 기록 |

필터는 이 셋뿐입니다. **확인 필요 / 확인 완료는 이슈의 처리 상태이지 따로 볼 데이터 묶음이 아닙니다** —
필터로 만들어 두면 '이슈 없음'·'이슈만'과 뜻이 겹쳐서 지금 무엇을 보고 있는지 헷갈립니다. 상태는
달력 배지·일자 요약·데이터 관리 목록에서 보고 바꿉니다(바꾸면 '이슈 없음'에 들어오고 나가는 데이터가 달라집니다).
예전 버전에서 저장해 둔 `issue_open`/`issue_resolved` 값은 '이슈만'으로 읽습니다.

- 한 기록은 어떤 필터에서도 **한 번만** 셉니다(출처가 여럿이어도 중복 집계하지 않습니다).
- 한 기록이 이슈 파일과 정상 파일 양쪽에서 왔다면 '이슈 없음'과 '이슈만' 양쪽에 나옵니다 —
  그래서 상태별 합이 전체보다 클 수 있습니다(통계 화면에 그렇게 적혀 있습니다).
- 고른 값은 브라우저/앱에 남아서 탭을 옮기거나 다시 켜도 유지됩니다.

### 화면별로 어떻게 보이나

- **달력**: 이슈가 있는 날짜에 `확인 필요 n` / `확인 완료 n` 배지. 필터를 걸면 그 기준으로 지점 수·수집 시간이
  다시 계산되고, 남는 기록이 없는 날짜는 흐려집니다. **주행 시간(첫 기록~마지막 기록)은 파일별로 쪼갤 수 없어서**,
  하루가 일부만 걸러진 날짜는 주행 시간 합계에서 빠지고 그 사실을 표 아래에 적습니다.
- **일자 요약**: "이슈사항" — 그 날짜 기록이 어느 파일에서 왔는지 목록과 함께, 메모 수정 · 확인 완료로 변경 ·
  이슈 해제를 할 수 있습니다.
- **누적 지도**: 구역 색 점은 **언제나 그대로 그리고**, 그 위에 이슈 몫만큼만 회색 점을 겹쳐 올립니다.
  그래서 같은 자리에서 문제 없는 날과 문제 있는 날을 모두 달렸으면 **두 색이 함께 보입니다**(회색 점의 크기는
  그 칸에서 이슈 기록이 차지하는 비율 √ 이고, 전부 이슈인 칸만 완전히 회색이 됩니다). 지도 아래에 회색 점이
  몇 칸인지 안내가 뜨고, 칸 위에 커서를 올리면 그 칸의 이슈 기록 수를 알려줍니다. '이슈 없음'을 보고 있을 때는
  겹치지 않습니다 — 그 화면에 남은 기록은 정상 파일에서도 나온 것들이라 회색으로 표시할 이유가 없습니다.
- **누적 지도 · Coverage**: 같은 필터 버튼이 있고, **Coverage 캐시 키에 필터가 들어갑니다**
  (`coverageCalcKey`). 구역 경계·도로/건물 같은 정적 계산 키(`coverageGeometryKey`)에는 넣지 않아서,
  필터를 바꿔도 지도 데이터를 다시 받아오지 않습니다. 필터를 되돌리면 이전 계산 결과를 그대로 재사용합니다.
- **통계**: "이슈 현황"과 전체 / 이슈 없음 / 이슈 데이터 비교표 — **데이터 상태가 '전체'일 때만** 보여줍니다
  (이슈 없음·이슈만을 보고 있을 때는 그 표가 지금 화면의 숫자와 어긋나 보여서 아예 숨기고, 계산도 하지 않습니다). 구역·차량·장소·도로종류·날씨·시간대 막대와
  교통 시간대·조도·요일 막대에는 **이슈 데이터 몫이 같은 막대 안에 회색으로 겹쳐** 그려지고, 카드 아래에
  회색이 몇 개(몇 분)인지 적힙니다. 지도의 회색 점과 같은 색(`#7d8798`)입니다. 막대의 나머지 부분은
  고른 지역·차량의 색을 씁니다(교통 시간대·조도·요일 카드도 같은 색 규칙을 따릅니다).
- **데이터 관리**: "이슈 관리" — 파일명·메모 검색, 이슈만 보기, 상태별 보기, 메모 수정, 확인 필요 ↔ 확인 완료,
  이슈 해제(표시만 지우고 GPS 기록은 그대로 둡니다).
- **추천 주행**: 기본적으로 **확인 필요 이슈 데이터를 빼고** 계산하고, 화면에 `추천 계산 기준: 확인 필요 이슈
  데이터 제외`라고 적습니다. 아직 확인하지 않은 데이터로 "여기는 이미 충분하다"고 판단하지 않기 위해서입니다.
  이슈 데이터까지 포함해 보려면 '이슈만'·'확인 필요' 필터를 고르면 됩니다. 누적 지도가 저장한 Coverage 스냅샷이
  다른 데이터 상태로 계산된 값이면 한계 목록에 적고 신뢰도를 한 단계 낮춥니다.

### 성능 — 레코드마다 출처를 훑지 않는다

이슈 필터를 `EXISTS (record_sources 조인)` 으로 판정했더니 10만 건짜리 DB에서 화면 하나 여는 데 **7초**가
걸렸습니다(실측). 지금은 레코드마다 출처 마스크를 `driving_records.issue_mask` 에 저장해 두고, 조회는 비트
연산만 합니다.

- 마스크는 Import 직후(그 파일의 레코드에 비트를 OR)와 이슈 수정·복원 직후(그 파일의 레코드만 다시 계산)에만
  갱신합니다. 예전 DB 를 열면 컬럼을 붙이면서 한 번 전부 계산합니다.
- 이슈로 표시한 파일이 하나도 없으면 필터 조건을 아예 걸지 않습니다(전체 = 이슈 없음, 이슈 데이터 0건).
- Import 이력의 "파일별 레코드 수"는 데이터 관리 화면에서만 셉니다(`withRelatedRecords`).

실측(10만 건 · 파일 31개 · 이슈 5개): 전체 조회 127ms · 이슈 없음 7,112→**570ms** · 누적 지도 밀도 3,352→**331ms** ·
이슈 현황 2,144→**152ms**.

### 성능 — 화면 하나에 조회 한 번 (브라우저 모드)

브라우저 모드(IndexedDB)에는 SQL 이 없어서 **집계마다 전체 기록을 커서로 훑습니다**(8만 건에 약 0.4초).
통계 탭이 요약·장소·도로·날씨·시간대·이슈 몫·이슈 현황을 따로 물어보면 같은 8만 건을 열 번 넘게 훑어서
탭 한 번에 5초가 넘게 걸렸습니다. 그래서 **화면이 필요한 값을 한 번에 주는 묶음 API** 를 뒀습니다.

| API | 주는 것 | 브라우저 모드 스캔 |
|---|---|---|
| `getStatsBundle(filter, {withIssueShare, withIssueOverview})` | 요약 + 구역/차량/장소/도로/날씨/시간대 분포 + 그중 이슈 몫 + 이슈 현황 | **0번**(날짜 요약만 읽음) |
| `getAccumBundle(filter, cell)` | 요약 + 밀도 칸(이슈 몫 포함) + 지도 범위 | 1번 |
| `getIssueOverview(filter)` | 전체/이슈 없음/이슈 데이터 기록 수 + 출처 없는 기록 수 | 1번 |

통계 탭은 아예 원본 기록을 읽지 않습니다. 날짜 요약에 **분포 칸(`distCells`)** — 구역·차량·장소·도로종류·날씨·
파일 원본 시간대·이슈 마스크 조합별 기록 수 — 를 같이 저장해 두고, 통계는 그 수십 줄만 더합니다
(하루치 조합은 보통 수십 줄입니다). 요약 형식이 바뀌었으므로 예전 요약은 앱을 켤 때 한 번 다시 만듭니다
(`SUMMARY_VERSION 7`). 분포 칸이 아직 없는 날짜가 섞여 있으면 그때만 예전처럼 원본 기록으로 셉니다.

SQLite(데스크톱)는 같은 API 를 색인을 쓰는 SQL 로 답합니다 — 이슈 몫은 같은 `GROUP BY` 안에서 조건부 SUM 으로
세기 때문에 쿼리가 두 배로 늘지 않습니다. 저장소가 달라도 화면 코드는 같은 한 번의 호출만 합니다.

실측(8만 9천 건, 브라우저 모드): 통계 탭 5.3초 → 0.64초 → **7ms**(요약 기반) · 누적 지도 1.2초 → **0.44초**.
데스크톱(SQLite)도 같은 길을 씁니다 — 통계 묶음 466ms → **28ms**.

### 성능 — 지도 데이터 서버가 막혀 있을 때

Coverage 판정에 쓰는 도로·건물 데이터는 Overpass(무료 커뮤니티 서버)에서 받아옵니다. 미러 4개를 15초씩
순서대로 기다리도록 돼 있어서, 이 데이터를 못 받는 네트워크에서는 한 번 계산에 최대 1분이 걸렸고
**탭에 들어올 때마다 그걸 반복**했습니다(임시 결과는 다시 들어올 때 재시도하게 돼 있습니다).

- 미러당 대기를 **8초**로 줄이고,
- 미러가 전부 실패하면 **10분 동안은 아예 시도하지 않습니다**(그동안은 도로·건물 없이 바로 계산 — 결과는
  여전히 "임시"로 표시되고 추천 신뢰도도 낮춥니다).
- 왜 대체값으로 그렸는지와 언제 다시 시도하는지 안내 문구로 알려주고, **"커버리지 갭 보기"를 직접 누르면**
  "지금 다시 해봐"로 보고 곧바로 재시도합니다.

### 백업 · 서버 동기화

- 백업에는 Import 이력의 이슈(체크 여부·메모·상태·시각)와 **그 파일에서 나온 레코드 키**가 함께 들어갑니다.
- 복원·동기화 때 같은 Import 인지는 `파일명 | 파일 지문 | Import 시각`으로 가립니다(기기마다 id 가 다르므로).
- 이슈가 양쪽에서 다르게 수정됐으면 **`issueUpdatedAt` 이 최신인 쪽을 남기고, 메모를 임의로 합치지 않습니다**.
  밀려난 값은 `issueConflict` 로 남겨 데이터 관리·일자 요약에서 볼 수 있습니다.
- 레코드 출처(recordKeys)는 양쪽을 합집합으로 모읍니다 — 한쪽만 남기면 출처가 끊깁니다.
- 백업 복원이 만드는 `(백업 복구)` Import 는 **출처로 남기지 않습니다**. 남기면 모든 기록이
  "이슈 없는 파일에서도 왔다"가 되어 이슈 분리가 통째로 무너집니다(진짜 출처는 백업 안의 Import 이력이 되살립니다).

### 예전 데이터

이 기능 이전에 들어온 기록에는 출처 정보가 없습니다(마스크 `0`). 이런 기록은 **전체·이슈 없음 화면에 그대로
보이고**, 이슈 화면에는 나오지 않습니다 — 이슈라고 단정하지도, 지도에서 갑자기 사라지지도 않습니다.
출처 없는 기록이 몇 건인지는 통계의 이슈 현황에서 알려줍니다. 이슈 필드가 없던 예전 백업도 그대로 복원됩니다.
