# 주행 계획

> Route Viewer 문서 · [← README 목차로](../README.md#문서-목차)

## 주행 계획 — "그 시간에 나가면 어디부터 어떻게 돌까"

추천 카드가 **무엇이 부족한가**를 말한다면, 주행 계획은 그 답을 **하루 일정**으로 바꿉니다.
추천 탭 위쪽 "주행 계획"에서 운행 시간을 바꿔 보면 바로 다시 계산됩니다(계산은 즉시 끝납니다).

### 무엇을 입력하나

| 입력 | 기본값 | 설명 |
|---|---|---|
| 요일 | 평일 | 평일/주말에 따라 부족한 조건이 다릅니다 |
| 운행 시작 · 종료 | 09:00 ~ 18:00 | 바꿔 보고 싶은 시간 |
| 비교 기준 | 09:00 ~ 18:00 | **지금** 운행 시간 — 이것과 견줘서 무엇이 달라지는지 보여줍니다 |
| 차량 | 1대 | 여러 대면 같은 시간에 서로 다른 구역으로 나눕니다 |
| 구역 | 전부 | 오늘은 강남만 돌 것처럼 일부만 고를 수 있습니다 |

프리셋 버튼: **1시간 일찍 시작 · 1시간 늦게 종료 · 앞뒤 1시간씩 · 기본으로**.

### 어떻게 계획을 세우나 (순서대로)

1. 운행 시간을 **교통 시간대 경계**(출근 피크 07~10 …)와 **그날의 일출·일몰 경계**로 자릅니다.
   너무 긴 구간은 60분으로 나누고, 15분보다 짧은 꼬리는 앞 블록에 붙입니다.
2. 블록마다 그 시각의 조건(교통 시간대 · 조도)을 정하고, **그 조건에서 가장 부족한 구역**을 고릅니다 —
   점수는 추천 카드와 **같은 규칙**(부족도 점수)을 그대로 씁니다.
3. 조건 한 칸의 **남은 부족분을 장부처럼 깎아 나갑니다**. 한 칸을 채우면 자연히 다음으로 부족한 곳으로 옮겨갑니다
   (목표를 다 채운 칸에 하루 종일 머무르지 않습니다).
4. 구역을 옮기면 **이동 시간만큼 수집 시간이 줄어드는 것**을 값에 반영합니다 — 이동해서 얻는 것이 더 클 때만 옮깁니다.
   이동 거리는 **HD Map 도로망 최단 거리**(`RoadGraph.buildRouter` — 구역 중심을 가장 큰 연결 도로망의 가까운 노드에 붙이고
   Dijkstra)로 잡고, 도로망으로 이을 수 없는 구역 쌍(예: HD Map 이 없는 판교·시흥)만 **직선 거리**로 대신합니다.
   이동 시간 = 거리 ÷ 평균 속도(기본 30km/h). 블록 표에 어느 방법으로 쟀는지(도로/직선)와 거리가 나옵니다.
5. **A → B → A 처럼 블록마다 오가지 않게** 계획 가치에서 구역 변경 비용을 뺍니다 —
   `계획 가치 = 추천 점수 × 수집 가능 분 − 이동 시간 − 구역 변경 비용(10분)`, 부족분이 남은 구역을 최소 체류(60분) 전에
   떠나면 모자란 분만큼 더 뺍니다. 점수 차가 충분히 크면 비용이 있어도 옮깁니다. 이 비용은 판단에만 쓰고 실제 수집 시간은
   이동 시간만 뺍니다.
6. 같은 계산을 **비교 기준 운행 시간**으로 한 번 더 해서 차이를 냅니다.

### 무엇을 보여주나

- 시각별 표: `08:00~09:00 · 강남 · [교통: 출근 피크] [조도: 주간] · 수집 60분 · 이동 —분 · 이유`
- 요약: 예상 수집 시간 · 이동 시간(도로망/직선 기준) · 구역 변경 횟수 · 구역별 시간 · 그날의 일출/일몰
- 비교: `지금(09:00~18:00)보다 60분 더 모읍니다` + **새로 잡히는 조건**과 그 조건의 부족분을 얼마나 메우는지,
  반대로 **빠지는 시간**이 있으면 그것도 함께.

### 하지 않는 것 (한계)

- 이동 시간은 도로망 거리(또는 직선 거리) ÷ 평균 속도 어림값입니다 — 신호·정체·일방통행·주차 시간은 반영하지 않습니다
  (HD Map 도로를 양방향으로 봅니다).
- 계획의 수집 시간은 "그 시간에 그 구역에 있으면 계속 기록된다"고 본 **최대치**입니다(휴식·신호 대기를 빼지 않습니다).
- 날씨는 예측하지 않습니다. 구역 좌표가 없으면 조도(일출·일몰)를 계산하지 못하고 교통 시간대만으로 계획하며,
  그 사실을 화면에 적습니다.
- 순위·수치는 전부 통계 규칙이 정합니다(LLM 이 정하지 않습니다).
