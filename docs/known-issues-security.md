## 알려진 이슈

- **교통 시간대·조도 조건 — 아직 없는 것**: 공휴일은 평일로 셉니다(요일 구분은 토·일만 주말). 날씨는 파일 원본 문자열
  그대로라 표기가 다르면(`비`/`강우`) 다른 값입니다. 시간대는 `Asia/Seoul` 고정 오프셋만 지원합니다. 교통 시간대는 8개
  구간의 시각만 바꿀 수 있고 구간 추가·삭제·이름 변경은 없습니다. 요일·교통·조도·날씨를 골라 보는 복합 필터 화면과
  추천 기능은 없고 집계 API만 있습니다. 누적 지도(밀도·Coverage)에는 조건 필터가 없습니다(데이터 상태 필터는 있습니다).
- **자동 분석 — 아직 없는 것**: 지도 POI(OSM)를 이 환경에서 받지 못해 업무지구·학교·병원·시장·역 분류는
  코드만 있고 실제 데이터로 검증하지 못했습니다. 공식 어린이보호구역 공공데이터, IC·JC 이름, 터널·교량 구분,
  Turn-by-Turn 경로는 없습니다. HD Map 이 있는 강남·서초 밖에서는 자동 분석이 비어 있습니다.
- **세부 구역 추천 — 아직 없는 것**: 지도에서 세부 구역을 **자동으로 찾아주지 않습니다**(직접 등록해야 합니다).
  OSM POI(학교·병원·업무시설) 조회와 어린이보호구역 지정 데이터 연동, IC·JC 램프 이름, Turn-by-Turn 경로
  생성은 없습니다. HD Map 은 강남·서초만 있어서 다른 구역은 구간 없이 구역 단위로만 추천합니다.
  방향 판정은 25m 매칭 기준이라 고가·지하차도가 겹친 곳에서는 맞추지 못할 수 있습니다(그때는 "못 맞춤"으로 셉니다).
- **HD Map 우선 구축 구역 ①~⑫ — 경계(polygon)는 직접 그려야 합니다**: 협의체 자료에 ①~⑫ 경계가 없습니다.
  `[산자부E2E][데이터협의체]HDMap_구축지역(강남)_세부구역_260209` 폴더의 폴리곤 레이어는 **법정동 경계뿐**이고
  (`강남구.shp` 8개: 역삼·청담·삼성·대치·신사·논현·압구정·도곡 / `서초구.shp` 3개: 잠원·반포·서초), 나머지 레이어는
  전부 도로 선(Line)과 노드 점(Point)입니다. `강남_서초_도로_시각화_최종.qgz` 에도 ①~⑫ 레이어·메모리 레이어·내장
  좌표가 없습니다. 참고 이미지(PNG)는 사람이 위치를 확인하는 용도라 거기서 좌표를 역산하지 않습니다.
  → [통계] → **HD Map 우선 수집** → **구역 경계 설정**에서 지도에 직접 그려 저장합니다(WGS84 위경도).
  저장하면 **이미 들어와 있는 기록 전체**가 그 자리에서 다시 분류됩니다(재 import 불필요). 경계는 `meta` 의
  `hdmap_priority_polygons` 에 저장되고 백업/복원에 포함됩니다. 협의체 경계 파일이 생기면
  `src/data/hdmap-priority-areas.json` 을 채우는 길도 그대로 있습니다(직접 그린 경계가 우선).
  경계가 겹치면 겹친 자리의 기록은 두 구역에 모두 들어가고 화면이 그 사실을 경고합니다.
  숫자가 없을 때는 이유를 구분해 보여줍니다 — 경계 미설정 / 경계 안 기록 0건 / 계산 실패 / Coverage 미계산.
- **Import 이슈 — 아직 없는 것**: 이슈는 파일 단위로만 붙습니다(레코드 하나만 이슈로 표시할 수 없고, 한 파일에
  메모도 하나입니다). 이슈 종류/태그 분류, 담당자, 처리 이력(누가 언제 확인 완료로 바꿨는지)은 없습니다.
  회색 표시는 밀도 지도(원)와 통계 막대에만 있습니다 — Coverage Map 의 칸 색은 방문/미방문 판정을 나타내므로
  이슈 색을 겹치지 않았습니다(대신 '이슈 없음'으로 보면 그 기록을 뺀 Coverage 가 다시 계산됩니다).
  데이터 상태 필터로 하루가 일부만 남으면 주행 시간(첫 기록~마지막 기록)은 합계에서 빠집니다 —
  Import 출처별로 나눌 수 없는 값이라 그렇습니다(수집 시간·기록 수는 정확히 나뉩니다).
- **추천 주행 — 아직 없는 것**: LLM 은 연결돼 있지 않습니다(구조화 payload 와 지시문만 준비). Coverage 는 누적 지도에서
  한 번 계산해야 추천 점수에 들어가고, 조건별(요일·시간대·조도) Coverage 는 계산하지 않습니다. 실제 Edge Case 이벤트 로그가
  없어 모든 예상 Edge Case 는 조건 기반 추정입니다. 목표 기본값(피크 240분·4회 등)은 데이터가 아니라 정책 기본값입니다.
  공휴일은 평일로 셉니다. 추천 상태(기간 제외·완료 표시)는 기기마다 따로이며 백업·동기화에 포함되지 않습니다.
- **분류 설정도 서버 동기화로 퍼집니다.** `server.js`가 설정을 "나중에 올린 값 우선"으로 합치므로, 한 기기에서 교통
  시간대를 바꾸고 동기화하면 다른 기기가 다음 동기화 때 그 설정을 받아 재분류합니다.

- **`release/win-unpacked`의 패키지 앱은 3.1.1**이라 날짜 필터·지도 캡처가 들어 있지 않습니다(그 `app.asar`에는
  날짜 입력칸과 `fromDate` 조건이 없음). 3.1.2 설치 파일은 이번에 빌드하지 않았습니다 — `npm run dist`가 필요합니다.
- 데스크톱 앱의 지도 캡처는 창보다 큰 지도면 보이는 부분만 저장됩니다(브라우저 모드는 지도 전체).
  브라우저 모드 캡처는 배경 타일 서버의 CORS 허용(현재 OSM은 허용)에 기대고, Safari에서는 타일 흑백 필터가 빠집니다.
- **지역별 Coverage 요약 패널이 비어 있습니다.** `index.html`에 `#coverage-summary` 자리가 있고 E2E도 이 요약을
  확인하지만, 현재 코드에는 이 영역을 채우는 함수가 없습니다(선택한 한 구역의 상세 패널 `#coverage-detail`만 동작).
  그래서 E2E의 "요약에 강남 Coverage %가 표시된다" 1건은 이번 변경 전 코드에서도 실패합니다.
- **건물 데이터(Overpass) 대기가 길 수 있습니다.** 미러 4곳을 순서대로 각 15초 제한으로 시도해서, 미러가 응답하지
  않으면 첫 Coverage 계산이 수십 초 걸립니다(이번 점검 중 `overpass-api.de`는 HTTP 406을 반환). 이 경고가 E2E의
  "화면 콘솔 에러"로 집계돼 E2E 종료 코드가 1이 됩니다.
- **동기화로는 "지우기"가 전파되지 않습니다.** 수동 셀·구역 경계는 병합만 하므로, 한 기기에서 해제한 칸이 다른
  기기/서버에 남아 있으면 다음 동기화 때 다시 돌아옵니다.
- `release/`, `node_modules/`, `tooling/`이 `.gitignore`에 있어도 이미 Git에 추적되고 있고, `주행기록/`·`백업/`의
  실제 GPS 기록도 커밋돼 있습니다(`.gitignore`에서 주석 처리됨). 정리 방법은 아래 보안 주의사항 참고.

## 서버 동기화 보안 주의사항

`server.js`는 **신뢰할 수 있는 내부망 전용** 도구로 만들어져 있습니다. 현재 동작:

- 기본 `HOST`가 `0.0.0.0`이라 같은 네트워크의 모든 기기에서 접속됩니다.
- `GET /api/route-data`는 **인증이 없습니다** — 서버에 모인 모든 GPS 기록·구역·설정을 누구나 받을 수 있습니다.
- `ROUTE_VIEWER_WRITE_TOKEN`을 설정하지 않으면 **누구나 PUT으로 데이터를 넣을 수 있고**, 그 데이터는 동기화하는
  모든 데스크톱 앱에 병합됩니다.
- 정적 파일 핸들러가 프로젝트 폴더 전체를 내려주므로, 이 폴더에서 서버를 띄우면 `/.git/…`, `/백업/*.json`,
  `/주행기록/*.xlsx` 같은 파일도 그대로 다운로드됩니다.
- 자동 업데이트는 입력한 서버 주소(`<주소>/updates`, 보통 `http://`)에서 받으며, 설치 파일에 코드 서명이 없습니다
  (`signAndEditExecutable: false`). 같은 네트워크의 공격자가 업데이트 파일을 바꿔치기할 수 있습니다.

권장: `HOST=127.0.0.1` 또는 방화벽으로 접근 제한, `ROUTE_VIEWER_WRITE_TOKEN` 필수 설정, 가능하면 HTTPS 리버스
프록시 뒤에서 운영하고, 개인 데이터가 없는 별도 폴더에서 서버를 실행하세요.
